如何升级Anaconda，并且在PATH保留旧版本Python？

1. 缘起

  • 自从2023年更新到 Python 3.10.9 以来，我编写了很多项目，都是依赖于这个版本的Python
  • 最近，我需要更新到 Conda 25.x，发现单纯更新Conda会引发问题（见上一篇博客），因此必须卸载目前的Python和Anaconda，重新下载最新版安装包，然后安装。
  • 但这样会产生一个严重的问题：我之前使用 Python 3.10.9 + Venv，是在把它添加到环境变量 PATH，使 Python 3.10.9 作为全局 Interpreter 的情况下，进行项目开发的
  • 一旦升级全局 Python 版本，那将会是一场灾难😂，因此，我必须想办法在升级整个 Anaconda 的前提下，保住全局的 Python 3.10.9 运行环境，确保已经开发完毕的项目，稳定运行。

2. 解决方法

  1. 首先，我卸载现在的Anaconda 2023，也就是 Python 3.10.9 配套的 Anaconda
  2. 然后，我安装Anaconda 2025，但是不把Base环境的Python添加到PATH。
  3. Instead，我创建一个py310的conda虚拟环境，把这个Interpreter添加到PATH。
  4. 这样，就能保证我的默认Python是3.10.9，同时Conda升级到25，还能运行所有Venv😆！

11. 解决 VenvTools 兼容性问题

我之前曾经开发过一个Venv虚拟环境的配置工具，起名为VenvTools，开源在GitHub上：

  • SirJackie/VenvTools: An Python Virtual Environment Migration Toolset.
  • https://github.com/SirJackie/VenvTools

主要是解决这几个痛点：

  • Python创建的Venv虚拟环境，是不能通过“剪切粘贴”移动到其他位置的，一旦路径改变，就会出错无法使用
  • 并且，需要把Venv从一台电脑，迁移到另一台电脑时，缺乏好的方法（一般使用导出 requirements.txt 的方法，但这种方法，恢复时需要网络；并且在没有指定版本的情况下，不能保证恢复后版本完全相同）
  • 所以，我设计了一套迁移工具，只需要运行程序，就能导出 wheels + requirements.txt 的全量安装包，帮助您轻松迁移Venv！

但我发现，使用本文的方法，升级 Anaconda 后，虽然 Python 保持 3.10.9，但是 VenvTools 就不能读取之前缓存的 wheels 文件，来帮助构建Venv，而是会报错：

  • 那是因为：Anaconda 升级后，重新创建了 Python 3.10.9 环境
